# 향후 작업: CPU 코어 배치별 스트리밍 성능 비교

- 기록일: 2026-10-07
- 상태: **예정 / 미실행**. 지금은 affinity 설정이나 서비스 배치를 변경하지 않는다.
- 목표: 실제 카메라를 송출하면서 코어 배치에 따른 영상 지연과 안정성을 비교하고,
  측정값을 근거로 운영 배치를 선택한다.
- 하드웨어: Raspberry Pi 4, Cortex-A72 4코어, CPU 0~3, 코어당 하드웨어 스레드 1개.

## 비교할 배치 후보

| 조건 | 영상 처리·인코딩 | 탐지 연산 | 목적 |
| --- | --- | --- | --- |
| A: 기준 | CPU 0~3 자유 배치 | CPU 0~3 자유 배치 | 현재 기본 배치의 성능 확인 |
| B: 두 코어씩 분리 | CPU 0·1 | CPU 2·3 | 영상과 추론의 CPU 경쟁을 줄이는 효과 확인 |
| C: 영상에 세 코어 | CPU 0·1·2 | CPU 3 | 영상 자원을 늘렸을 때 송출과 추적 지연의 변화 확인 |
| D: 추론만 제한 | CPU 0~3 허용 | CPU 2·3 | 영상 스케줄링 자유도를 유지하면서 추론 실행 범위를 제한 |

이 표는 후보이며 최적 배치를 확정한 것이 아니다. C에서도 추론 스레드 수는 우선
다른 조건과 동일하게 유지해 affinity 효과부터 비교한다. 추론 스레드 수 변경은
별도 시험으로 분리한다. MediaMTX·서보·ONVIF·OS는 첫 비교에서 기본 배치를 유지한다.

## 구현 전 확인

- 영상과 탐지는 현재 같은 카메라 송출기 프로세스 안에 있다. 프로세스 전체를 한 코어에
  묶는 설정만으로 두 기능을 분리할 수 없다.
- GStreamer, x264, OpenCV 내부 작업 스레드의 실제 TID와 affinity를 확인한다.
  탐지 스레드 하나를 고정했다고 내부 추론 스레드 전체가 배치됐다고 가정하지 않는다.
- 재시작·시청자 재접속 후 생성되는 새 스레드에도 의도한 배치가 적용되는지 확인한다.
- CPU affinity는 실행 가능한 CPU를 제한하는 기능이다. 해당 코어에서 다른 작업을
  배제하는 전용 코어 설정이나 실행 우선순위 보장은 아니다.
- 현재 운영 조건과 동일한 카메라·송출·탐지 경로에서 먼저 검증한다. 구조를 크게
  바꿔야 한다면 그 변경 효과와 affinity 효과를 구분해서 기록한다.

## 시험 조건

1. 실제 카메라 1280×720/30fps, 현재 x264 인코더 설정과 최신 프레임 정책을 유지한다.
2. 같은 PC·Qt 플레이어·네트워크·시청자 수·재생 버퍼 설정을 사용한다.
3. RTSP TCP, RTSP UDP, WebRTC는 각각 별도의 비교 묶음으로 시험한다.
   한 묶음 안에서는 전송 방식과 플레이어 설정을 바꾸지 않는다.
4. 각 배치에서 추적 OFF/ON을 나눠 측정한다. ON 시험은 동일한 사람 이동 동선이나
   반복 가능한 입력을 사용하고, 서보 장착 상태와 이동 조건도 기록한다.
5. 조건별 준비 시간 30초 후 180초 측정, 최소 3회 반복한다. 조건 순서를 교대하고
   냉각·온도·클럭·스로틀링 및 다른 부하 작업을 기록한다.
6. 실행 중인 서비스, 모델/소스 버전, 실제 스레드별 affinity, 원본 로그 경로를 저장한다.

## 측정 지표와 선택 기준

| 지표 | 확인할 내용 |
| --- | --- |
| Qt 실제 표시 지연 | 평균·p95·최대. 화면 시간 표시나 촬영 등 별도 측정 방법을 먼저 정한다. |
| 영상 출력 | 출력 버퍼율, 프레임 간격 p95·최대, 멈춤·누락·디코딩 오류 |
| 탐지 | 추론 시간, 결과 프레임 나이, 오래돼서 폐기한 결과 수 |
| 제어 | 명령 처리 시작부터 GPIO 호출 반환까지의 시간. 물리 이동 완료와 구분 |
| 자원 | 프로세스·스레드별 CPU, RSS, 문맥 전환, 온도·클럭·스로틀링 |

기존 [계측 도구](README.md)를 사용하되 프레임 간격 집계와 Qt 표시 지연 측정은
시험 전에 추가한다. Pi의 인코딩 출력 버퍼율이나 추론 시간을 Qt 표시 지연으로
대체하지 않는다.

30fps 수준의 영상 흐름과 안정성을 유지하는 조건 중 실제 표시 지연의 p95가 낮은
배치를 우선 검토한다. 탐지 결과 나이와 제어 응답이 악화되는지도 함께 판단한다.
차이가 반복 시험의 변동 범위 안에 있으면 기본 배치를 유지하는 선택도 가능하다.
