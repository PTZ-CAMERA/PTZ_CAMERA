# 2026-10-08 PTZ ONVIF 인증 및 Pi 서보 상태 확인

## 사용자 요청

VMS/Qt에서 보낸 PTZ 로그의 의미를 확인하고, Raspberry Pi 쪽 모터 제어 준비 상태와
ONVIF 인증 문제 여부를 점검했다. 실물 장시간 시험은 수행하지 않았다.

## 확인된 Pi 서비스 상태

- `ptz-servo.service`: `active (running)`
- `ptz-onvif.service`: `active (running)`
- 내부 서보 제어 TCP: `127.0.0.1:5000`
- ONVIF HTTP: `0.0.0.0:8080`
- GPIO 소유자는 `ptz-servo.service` 하나로 유지된다.

## 실제 로그에서 확인한 흐름

ONVIF 요청이 Pi ONVIF 서비스에서 내부 서보 서비스로 전달됐다.

```text
ONVIF:ABS:90.000000,90.000000
PAN: 97 deg ... PAN: 90 deg
TILT: 87 deg ... TILT: 90 deg
```

따라서 ONVIF → loopback RPC → 서보 컨트롤러까지의 소프트웨어 경로는 동작한다.
서보 위치 센서가 없으므로 `PI_ACKNOWLEDGED`는 명령 수락을 뜻하며 실제 기계적 도착을
확인하는 응답은 아니다.

## 후속 확인이 필요한 사항

`ptz-onvif.service` 로그에 다음 메시지가 반복됐다.

```text
ONVIF authentication rejected
```

이 메시지만으로 인증 장애를 확정할 수 없다. Digest 인증의 최초 무인증 요청과
401 challenge 이후 인증 재요청에서도 나타날 수 있고, 실제 서보 명령 도달 로그도
확인됐다. 앞선 대화에서 인증 문제라고 단정한 설명은 정정한다. 요청별 최종 HTTP
상태와 SOAP 본문을 확인해야 한다. VMS가 HTTP 200만 확인하는지도 아직 확인하지 않았다.
VMS는 SOAP Fault를 함께 검사해야 한다.

계정은 Pi의 private 인증 설정을 사용하며 비밀번호는 저장소 문서에 기록하지 않는다.

또한 `AbsoluteMove(Center)` 직후 `PTZ_STOP`이 전송되는 로그가 있었다. `Stop`은
`ContinuousMove`의 버튼 release에 사용하고, Center가 `AbsoluteMove`라면 즉시 Stop을
보내지 않도록 Qt/VMS 동작 순서를 확인해야 한다.
