# 2026-10-03 사람 자동 추적 작업

어제 중단한 Raspberry Pi 4 C++ 사람 탐지·자동 PAN/TILT 기능을 이어서 검증했다.
기존 Git 작업 트리의 수정 사항을 유지했고 GitHub에는 푸시하지 않았다.

## 서보 코드 기능별 분리

`pi/servo_test/src/main.cpp`에 있던 구현을 `servo_control`, `center_button`,
`keyboard_control`, `tcp_server`, `command_protocol`의 `.cpp/.h`로 나눴다.
GPIO 번호·각도 제한·TCP 포트·버튼 설정은 `config.h`로 모았다.
`main.cpp`는 실행 모드, 초기화, 입력 대기, 종료 흐름을 담당한다.
CMake에 분리한 소스를 등록하고 Raspberry Pi에서 빌드를 완료했다.

실제 GPIO 대신 가짜 pigpio 함수와 별도 TCP 포트를 사용하는 임시 시험에서
분할·연속 명령, CRLF, Qt 상태 알림, 잘못된 명령·긴 입력 처리, 자동 이동,
수동 제어의 추적 해제, 각도 clamp, 버튼 debounce, 키 입력, SIGTERM 정리를
확인했다. 이 시험은 실제 모터 구동 검증이 아니다.
실행 중인 systemd 서비스는 재시작하지 않았으며, 새 버전 적용은 설치 스크립트를
실행할 때 이루어진다.

## 확인한 결과

- `ptz-servo.service`와 `ptz-camera.service`는 계속 실행 중이다. MediaMTX는
  시청자가 있을 때만 카메라 송출기를 시작한다.
- 실제 IMX219 → GStreamer → MediaMTX → RTSP 경로에서 FFmpeg가 영상을
  디코딩했다. 모델은 사람 사진에서 박스를 반환했고, 실제 카메라 장면에서는
  사람이 확인되지 않아 `NO_DETECTION`을 전달했다.
- Qt와 같은 TCP 수신 방식으로 `CAMERA:CONNECTED`, `NO_DETECTION`,
  `CAMERA:DISCONNECTED`를 받았다. 내부 시험 명령으로
  `DETECT:person,0.900000,640,360,0,0,90,90`도 받았다.
- 내부 자동 제어 명령 `AUTO:MOVE:1,1`로 PAN/TILT 각도 로그가 각각 91°가
  됐다. `PTZ:CENTER` 후 두 축은 90°로 복귀했고 `TRACK:STATUS`는
  `TRACK:OFF`였다. 작은 각도 명령이 pigpio에 전달됐다는 검증이며,
  실제 사람이 움직일 때 따라가는 방향·정확도 검증은 아니다.

## 지연 조사와 선택

송출과 탐지를 함께 실행해 `Person analysis` 로그의 입력 프레임 나이,
추론 시간, 추론 뒤 프레임 나이를 비교했다. 짧은 현장 시험 결과다.

| 설정 | 입력 프레임 나이 | 추론 시간 | 추론 뒤 프레임 나이 | 판단 |
| --- | --- | --- | --- | --- |
| 입력 5fps, DNN 2스레드 | 약 210~378ms | 약 284~319ms | 약 529~674ms | 600ms 제한으로 버려지는 결과가 많았다. |
| 입력 10fps, DNN 2스레드 | 약 151~253ms | 약 289~311ms | 약 440~564ms | 입력 영상이 더 신선해진 구간이 있었다. 현재 선택. |
| 입력 10fps, DNN 3스레드 | 약 188~302ms | 약 292~368ms | 약 541~607ms | 모델 단독 벤치마크와 달리 송출 중에는 개선되지 않았다. |

따라서 실제 서비스는 **640×360 영상 최대 10fps 입력, OpenCV DNN 2스레드**로
설정했다. 추론이 입력보다 느릴 때는 대기 중인 오래된 프레임을 버린다.
이 시험에서의 프레임 나이는 추론 결과가 나온 순간 기준이며 Qt 화면 표시 지연이나
실제 서보 반응 시간을 포함하지 않는다. 사람을 두고 장시간 시험해야 제어 품질을
판단할 수 있다.

## 코드·문서 정리

- 카메라 송출기는 `CAMERA:HELLO`로 서보 서비스에 자신을 등록한다. 단순
  `TRACK:STATUS` 조회는 이제 Qt에 카메라 연결 알림을 보내지 않는다.
- 자동 서보 명령은 등록된 Pi 내부 연결에서만 받는다. `TRACK:ON/OFF`, 수동
  명령 우선권, 각도 제한은 서보 서비스에서 처리한다.
- 코드의 역할별 파일과 전체 명령 흐름은 [동작 구조](../architecture.md)에
  정리했고, 기술을 선택한 이유와 측정값은
  [기술 선택 기록](../technology_decisions.md)에 반영했다.

## 아직 필요한 현장 확인

카메라 앞에서 사람이 좌우·상하로 움직일 때 PAN/TILT의 **실제 회전 방향**,
사람을 놓친 뒤 재탐지, 버튼 중앙 복귀, 수동 명령의 자동 추적 해제를 확인한다.
현재 테스트에서는 실제 사람이 카메라에 없었으므로 자동 추적의 물리적 성능은
확정하지 않는다. Qt UI가 `trackingInfoReceived`를 화면에 표시하는지는 PC의
별도 프로젝트에서 확인해야 한다. 간헐적 핑크 프레임 원인도 여전히 미확정이다.

### 서보 디렉토리 정리

기능별 파일을 `src/servo`, `src/button`, `src/keyboard`, `src/network`,
`src/protocol` 디렉토리로 이동했다. 각 디렉토리에 헤더와 구현을 함께 두고,
`main.cpp`와 공통 `config.h`는 `src/`에 유지했다. include 경로와 CMake를
수정해 다시 빌드했다. 실행 중인 서비스는 기존 버전을 유지한다.
