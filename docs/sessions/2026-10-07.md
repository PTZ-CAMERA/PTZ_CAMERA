# 2026-10-07 ONVIF 주소 조회 추가

## 목표

사용자 확인: **Qt가 우리 Pi의 RTSP URL을 조회**한다. 외부 ONVIF 카메라에서
Pi가 영상을 가져오는 기능은 이번 작업 범위가 아니다.

## 구현과 적용

- `pi/onvif_service`: C++17/CMake, 기능별 xml/protocol/network 디렉토리.
- namespace-aware Expat XML, libuuid 장치 ID, 비블로킹 HTTP/UDP poll 루프.
- WS-Discovery ProbeMatches와 Device/Media 주소·프로파일·스트림 URL 조회 지원.
- `onvif_probe`, `onvif_query` C++ 도구와 protocol/HTTP CTest 추가.
- systemd `ptz-onvif.service` 설치·부팅 활성화·실행. 임시 서비스 계정 DynamicUser 사용.
- HTTP `http://192.168.0.92:8080/onvif/device_service`.
- Media `http://192.168.0.92:8080/onvif/media_service`.
- RTSP 응답 `rtsp://192.168.0.92:8554/cam`, profile token `main`.
- 기존 영상/서보 서비스는 재시작하지 않았다. 시험 전 추적 상태는 `TRACK:OFF`였다.

## 확인

1. 빌드 완료, CTest 2개 통과. namespace/잘못된 토큰/DTD 처리, 분할 수신,
   잘못된 HTTP 경로·중복 헤더·큰 본문을 검증했다.
2. 실제 eth0에서 multicast Probe를 보내 Device XAddr를 받았다.
3. C++ HTTP 클라이언트로 GetServices → GetProfiles → GetStreamUri를 수행했다.
4. 반환 URL을 FFprobe에 전달해 H.264/Constrained Baseline/1280×720을 확인했다.
5. 설치 후 서비스 계정에서도 검색·URL 조회를 다시 확인했다.

## 같은 세션 후속: 사용자 지정 로그인 구현

사용자가 지정한 계정으로 ONVIF HTTP Digest와 영상 read 인증을 추가했다.
비밀번호는 문서에 기록하지 않고 `/etc/ptz-camera/access.conf`(root/0600)에 저장했다.
ONVIF는 LoadCredential로 읽고, MediaMTX 설정은 계정을 포함하는 private 파일로 생성한다.
초기 원형의 인증 미지원 상태는 이번 후속 작업에서 변경됐다. WS-Security UsernameToken과
TLS 및 전체 ONVIF 적합성은 여전히 미지원이다.

- CTest 3개 통과: 기존 프로토콜/HTTP, Digest 인증 성공·실패, 재사용 방지, URI 바인딩,
  병렬 요청 도착 순서 변경.
- 실제 ONVIF: 무인증/잘못된 비밀번호 401, 정상 계정으로 프로파일/URL 조회 성공.
- 실제 RTSP: 외부 LAN 주소의 무인증/잘못된 비밀번호 401, 정상 계정 200/SDP.
- Pi 내부 loopback 영상/metrics 접근 유지. FFprobe로 H.264 1280×720 확인.
- ONVIF·카메라 서비스에 적용하고 재시작했다. 서보 서비스는 재시작하지 않았다.
- 계정 생성/변경/재설치 도구, Qt 인증 콜백 연결 문서를 추가했다.
- RTSP 확인 도구의 초기 인증 실패는 `troubleshotting.md`에 조사·해결 과정을 기록했다.
- 실제 PC Qt의 인증 콜백과 플레이어 계정 전달은 별도 프로젝트에서 확인해야 한다.
- GitHub에는 푸시하지 않았다.

## 후속: ONVIF PTZ 제어 전환

AbsoluteMove/RelativeMove/ContinuousMove/Stop/GetStatus와 설정·노드 조회를 추가했다.
서보에는 순수 궤적 계산 모듈과 20ms 갱신 루프, loopback RPC를 추가했다. 공유 각도·속도
제한을 공통 헤더로 모았고 외부 PTZ 문자열은 거부한다. TRACK/탐지 알림은 기존 TCP다.

ONVIF·서보 서비스를 새 버전으로 적용했다. 서보 재시작은 원래 시작 동작대로 90°를
출력했다. 이후 인증된 GetStatus와 0변위/0속도/Stop을 확인했다. 무인증 401도 확인했다.
최종 빌드·ONVIF/궤적/가짜 GPIO 테스트가 모두 통과했고 중단 이후 상태 조회도 성공했다.
실제 비영 이동이나 PAN 방향 보정을 완료했다는 의미는 아니다.

Qt 개발 쪽에는 [PTZ 변경 요청서](../onvif_ptz_qt_migration.md)를 전달한다.
서비스는 실행 중이며 GitHub에는 푸시하지 않았다.
